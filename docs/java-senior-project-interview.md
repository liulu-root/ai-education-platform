适用对象：8 年 Java 开发经验，准备高级后端、资深研发、后端负责人或 AI 应用后端岗位。

依据：2026-09-06 当前工作区源码、数据库迁移、配置和测试文件，包含尚未提交的实现。本资料是源码阅读与面试准备结果，没有运行应用或测试，也没有验证真实供应商、Milvus 集群或生产性能。

共 120 道主问题，每题包含追问和回答要点。P0 为必须掌握，P1 为深入准备，P2 为进一步扩展。每节列出的类名可用于 IDE 全局定位；文末提供源码入口链接。

## 第一组：项目介绍、架构和技术取舍（01—10）

### 01【P0】请用三分钟介绍这个项目，你认为真正的技术难点是什么？

**连续追问：** 为谁解决什么问题？为什么需要 AI？你负责哪个部分？怎样证明业务价值？哪项设计最能体现你的经验？

**回答要点：** 先讲学习者、教师、审计员三个角色以及助教、批改、路径、风险、干预的业务关系。主线是将不确定的模型生成纳入可追踪的业务流程：权限来自服务端，评分与风险来自确定性逻辑，通知必须经人工审批。技术难点重点选两个讲透，例如会话并发与取消、预算控制与上下文重试；避免逐个背 API。

**项目依据：** `TutorService`、`AiGateway`、`ToolExecutionMiddleware`。个人职责和业务收益需要补充自己的真实经历；仓库不能证明你的职责、用户量或降本比例。

### 02【P0】为什么采用模块化单体？什么时候才值得拆微服务？

**连续追问：** 你会先拆哪一个模块？拆分后多出哪些一致性问题？只按 Controller 拆服务可以吗？

**回答要点：** 当前单体使认证上下文、事务、部署和本地演示较简单。拆分依据应是独立扩缩容需求、故障影响、团队边界和发布频率，而非功能数量。模型调用长连接、知识索引批处理、学习分析的资源模型不同，可以作为候选。拆分后要重新设计跨服务身份、审计、幂等、超时预算和消息一致性。

**项目依据：** 包级业务模块共享一个应用、数据库和 `AiGateway`。能描述演进方案，但不要声称已有微服务治理。

### 03【P0】画出一次助教提问的完整调用链，并标出失败点。

**连续追问：** 会在哪一步访问数据库？在哪一步产生模型费用？哪里跨线程？什么时候保存用户问题和回答？

**回答要点：** Trace → Security → TenantContext → TutorController → TutorService 虚拟线程 → 会话归属/租约 → 检索与画像 → 历史/摘要 → 上下文构建 → 保存 USER → AiGateway 检查/预算 → 模型流 → 审计 → 保存 ASSISTANT → 返回 done → 释放租约。摘要也可能单独调用模型。

**项目依据：** `TutorService.run/invoke`。必须指出：用户问题成功保存后，主模型仍可能失败；费用产生后，审计或业务落库仍可能失败，因此不存在覆盖整条链的数据库原子事务。

### 04【P0】为什么所有业务不直接调用模型，而要经过 AiGateway？

**连续追问：** 网关会不会成为上帝类？哪些规则应留在业务层？新增供应商需要改哪些代码？

**回答要点：** 公共能力包括输入策略、脱敏、预算、模型适配、输出检查、审计和指标。批改公式、学习路径顺序、会话重试条件属于业务编排，不应散进模型客户端。进一步演进可把计量、审计、策略拆成边界清楚的协作者，避免网关承担无限分支。

**项目依据：** `AiGateway.execute/executeStream` 与 `AiModelClient`。同步和流式路径存在重复逻辑，适合讨论统一调用生命周期，而非为消除几行重复牺牲取消语义。

### 05【P1】这个项目使用了哪些设计模式？为什么不直接引入 AI 框架？

**连续追问：** 策略模式和适配器模式分别体现在哪？Middleware 是责任链吗？自己封装的成本是什么？

**回答要点：** `AiModelClient`、`EmbeddingService`、`VectorStore` 是端口与可替换实现；供应商实现承担协议适配；`SensitiveToolHandler` 用工具名注册执行器。Middleware 在当前代码中更多是显式前后处理流程，不能仅凭名字断言已经存在可动态组合的责任链。自行封装便于理解和控制，但协议兼容、重试、观测和升级成本由团队承担。

**项目依据：** `@ConditionalOnProperty` 和构造器注入。是否采用框架，应比较所需能力、可测试性和维护成本，而不是用框架数量衡量架构水平。

### 06【P0】为什么评分、学习路径和风险分由代码决定，而不是交给模型？

**连续追问：** 规则一定公平吗？模型解释与规则结果矛盾怎么办？低温度能否确保稳定？

**回答要点：** 数值决策要求可复算、可审查、可版本化；语言模型适合解释和反馈。确定性只保证相同输入和规则产生相同结果，不保证业务合理性。关键数值通过结构化字段展示，解释也需一致性评测。提示词要求模型“不得修改顺序”只是软约束。

**项目依据：** `GradingService.evaluate`、`LearningPathService.createItems`、`LearnerRiskService.assessLearner`。规则的适用范围和校准方法，比“用了规则引擎”这个说法更重要。

### 07【P1】为什么选 JdbcTemplate，而不是 JPA 或 MyBatis？

**连续追问：** SQL 显式有什么好处？代价是什么？如何避免租户条件漏写？Map 返回值会带来什么问题？

**回答要点：** 当前 SQL 较直接，事务、条件更新和行锁容易审查；没有复杂对象图需求。代价是映射重复、字段重命名风险、分页与租户约束依赖人工纪律。可用类型化查询结果、集中资源授权和 Repository 契约测试改进。选择 ORM 不会自动解决所有越权或并发问题。

**项目依据：** 多个 Repository 使用 `queryForMap/queryForList`，核心会话使用 record 映射。可以讨论编译期类型安全与开发速度的取舍。

### 08【P0】项目目前最值得优先生产化的三件事是什么？

**连续追问：** 为什么不是先上 Redis 或 Kubernetes？怎样估算投入与收益？

**回答要点：** 先按错误后果排序：资源授权闭环、模型调用和审计的可靠性、知识索引状态与一致性；再结合实际负载补配额预占、并发限额和压测。每项说明用户影响、触发条件、实施范围和验收指标。明确区别功能缺口、代码风险与已经复现的故障。

**项目依据：** 当前预算先查后用、索引先写库后写向量、课程授权尚不完整。优先级是面试中的论证题，不是仓库已有生产事故记录。

### 09【P1】模型不可用时，业务是否还能工作？你如何设计降级？

**连续追问：** 助教可以返回什么？批改分数已算出为何仍失败？风险评估和风险解释是否应分开？

**回答要点：** 逐场景定义降级：风险纯规则接口可独立工作；批改可考虑先保存提交和规则结果，将文字反馈标记待生成；学习路径可先返回确定性活动；助教可返回检索资料和明确的能力受限提示。安全阻断和预算拒绝不是应被绕过的可用性异常。

**项目依据：** 当前批改、学习路径在 AI 成功后才保存业务结果，不能声称已经支持上述降级。`LearnerRiskService` 有不生成 AI 解释的路径。

### 10【P0】你如何证明项目做得好，而不只是“功能能点通”？

**连续追问：** 技术指标与业务指标分别是什么？有没有基线？怎么做实验？

**回答要点：** 技术侧衡量 TTFT、完成耗时分位数、错误率、取消传播时间、每次成功任务 Token/费用、重复副作用数、跨租户负样本通过率。业务侧衡量引用可核验率、教师修改反馈比例、复核工作量与学习任务完成情况。所有提升要有测试集、时间范围、样本量和对照条件。

**项目依据：** 当前审计和指标提供部分原始信号，不能从其存在推导已有 SLA 或业务收益。

## 第二组：Java 21、并发、内存与异常（11—20）

### 11【P0】为什么在 TutorService 使用虚拟线程？它能提升什么，不能提升什么？

**连续追问：** 与固定线程池相比差异在哪？CPU 密集任务适合吗？是否所有 Servlet 请求都已切成虚拟线程？

**回答要点：** 该流程主要等待模型网络和数据库，虚拟线程有助于降低大量阻塞任务占用平台线程的成本，不会让模型推理或 CPU 计算本身变快。代码显式创建助教和模型流虚拟线程，不能推断所有 Servlet 工作线程也改变了。需要依然限制上游并发、连接数和内存。[Java 虚拟线程设计说明](https://openjdk.org/jeps/444)。

**项目依据：** `TutorService.chatStream` 和 `OpenAiCompatibleModelClient` 的每任务虚拟线程执行器。

### 12【P0】用了虚拟线程，为什么还必须限流与隔离？

**连续追问：** 一万个请求同时等待模型会怎样？Semaphore 应放在哪？排队时间是否计入超时？

**回答要点：** 稀缺资源仍包括供应商并发与 Token 配额、数据库连接、套接字、缓冲区和预算。可按租户、场景、模型设置并发许可；获取许可应有截止时间，排队有上限，取消必须能退出队列。不能用“虚拟线程很便宜”代替容量规划，也不能在持有数据库行锁时等待上游许可。

**项目依据：** 当前同会话租约只限制一个 conversation 的并发，不是整个租户或模型的全局隔离器。

### 13【P0】为什么 TenantContext 不会自动跟着异步任务走？如何正确传播？

**连续追问：** MDC 呢？线程池复用会怎样？为什么不直接使用 InheritableThreadLocal？

**回答要点：** 当前使用普通 `ThreadLocal`。调用方先捕获不可变租户值，工作线程用 `TenantContext.open` 建立作用域，结束时恢复或清除；MDC 也显式设置和清理。线程池、回调线程与任务的生命周期不同，不能依赖隐式继承。传递业务上下文也不等于传递 Spring Security 或数据库事务。

**项目依据：** `TenantContext.Scope`、`RequestContextFilter`、`TutorService.chatStream`。网关异步审计捕获 tenant/trace 作为参数，减少回调线程上的隐式依赖。

### 14【P0】AtomicBoolean 为什么能防止重复完成？它能保证 exactly-once 吗？

**连续追问：** `if (!done) done=true` 为什么不行？成功回调和取消同时发生谁赢？CAS 成功后抛异常怎么办？

**回答要点：** 比较并交换保证一个内存状态迁移只有一个赢家，控制当前对象的终态处理。它不保证后续审计、数据库提交、消息交付一定完成，也不能跨 JVM 或进程重启生效。CAS 之后的清理与 completion 完成仍需异常安全设计。

**项目依据：** `AiGateway.executeStream`、`TutorController` 的 terminal、`TutorStream.cancel`。深入时画出成功、失败、取消三条路径竞争同一个终态的时序。

### 15【P0】CompletableFuture.cancel(true) 是否真的能停止模型请求？

**连续追问：** Future 已取消，网络是否还在读？响应体在取消后才到达怎么办？

**回答要点：** Future 状态变化不等于资源终止。当前适配器还取消 HTTP Future、关闭响应行流、取消派生 completion，并在响应稍后到达时检查 cancelled 再关闭。正确取消协议至少包括业务不再接收结果、上游资源释放和终态计量。

**项目依据：** `OpenAiCompatibleModelClient.generateStream/closeResponseLines`。不要把停止读取直接说成供应商已经停止计费，需要供应商使用量或账单核对。

### 16【P0】synchronized、volatile 和 AtomicReference 在这里分别解决什么？

**连续追问：** 可见性是否等于复合操作原子性？字符串缓冲区为什么要加锁？是否存在锁内 I/O？

**回答要点：** volatile 提供字段可见性，synchronized 保护临界区和复合状态，AtomicReference 支持引用原子替换。`partialContent` 被回调追加和取消线程读取，因此使用同一锁。`DeferredDelivery` 在同步方法中调用下游 consumer，下游可能写 SSE；在 Java 21 上，锁内阻塞值得检查虚拟线程 pinning，不能只看 synchronized 关键字就判定有性能问题。[JEP 444](https://openjdk.org/jeps/444)。

**版本追问：** JDK 24 的 JEP 491 改善 synchronized 导致的 pinning，面试中应区分编译目标和真实运行版本。[OpenJDK 24 发布说明](https://mail.openjdk.org/archives/list/announce%40openjdk.org/latest?count=25)。

### 17【P1】为什么耗时和截止时间用 System.nanoTime，而审计时间用 Instant？

**连续追问：** 系统校时会影响什么？数据库租约为什么还要考虑时钟？怎么测试跨天与超时？

**回答要点：** 单进程耗时使用单调时间差；跨系统事件记录使用可解释的墙上时间。当前租约到期时间由应用 Instant 计算，而 SQL 与数据库 CURRENT_TIMESTAMP 比较，跨机器时钟偏差会影响租约长度。可讨论由数据库统一生成租约时间，以及注入 Clock/计时器提升可测试性。

**项目依据：** `TutorService.Operation`、`TutorRepository.acquire/assertLease`、审计的 LocalDate。

### 18【P1】record 就一定是不可变对象吗？为什么 List.copyOf 还不够？

**连续追问：** `float[] embedding` 能否被修改？Map 内部对象呢？为什么参数快照很重要？

**回答要点：** record 固定的是组件引用，属于浅层约束。数组和嵌套对象仍可变；List.copyOf 只保护容器结构。对跨线程共享的向量、请求元数据或审批参数，应明确所有权或防御性复制。审批当前 `Map<String,String>` 配合 copyOf 比嵌套可变对象更易控制。

**项目依据：** `VectorChunk`、`AiModelRequest`、`ToolApproval`、`ProcessedOutput`。可以现场让候选人写一个带数组防御性复制的 record。

### 19【P0】异常包装和线程中断应该如何处理？

**连续追问：** ExecutionException 和 CompletionException 怎么拆？InterruptedException 能吞吗？为什么 finally 释放租约前临时清中断标志？

**回答要点：** 还原根因以保留业务错误代码；中断是取消协作信号，应恢复标志并转入清理。当前释放租约前通过 `Thread.interrupted()` 获取并清理标志，执行释放后再恢复，意在减少中断状态干扰数据库清理；释放失败仍可能依赖到期回收。

**项目依据：** `TutorService.failure/run`。也要审查清理异常是否掩盖原始异常，以及取消是否被误记为供应商失败。

### 20【P1】ConcurrentHashMap 能否保证知识索引的一致快照？

**连续追问：** 多个 Chunk upsert 到一半开始搜索会怎样？单个 value 内部数组可变怎么办？百万数据如何排 TopK？

**回答要点：** 容器线程安全不等于跨条目批量原子性；搜索可能观察到部分更新。当前先按租户课程筛选，再对候选计算相似度并全排序。若全索引 N、过滤后 M、向量维 D，主要工作约为 O(N + MD + M log M)。可讨论按租户课程分区、大小为 K 的堆、不可变索引快照或外部向量库。

**项目依据：** `InMemoryVectorStore.upsert/search`。不要把“没有 ConcurrentModificationException”误认为业务结果有快照一致性。

## 第三组：Spring、事务、认证和授权（21—30）

### 21【P0】Spring 事务在这里何时开始、何时结束？异步回调是否继承调用方事务？

**连续追问：** 模型流在线程 A 启动、线程 B 完成，事务在哪个线程？给返回 CompletableFuture 的方法加注解能解决吗？

**回答要点：** 在当前命令式 JDBC 路径中，事务资源与执行线程绑定。跨线程回调应通过受代理的独立事务服务完成数据库工作，不能默认继承发起线程事务。模型外部调用应位于短事务之外，审计或消息写入各自进入明确的事务边界。

**项目依据：** `AiAuditService.record`、`TutorRepository.saveLeasedMessage`；`AiGateway` 的异步回调调用注入的审计服务。源码的代理边界需要与实际调用关系一起分析。

### 22【P0】saveLeasedMessage 调用同类 saveMessage，是否因为自调用而没有事务？

**连续追问：** 内层 `@Transactional` 是否生效？外层事务还在吗？把内层改成 REQUIRES_NEW 有用吗？

**回答要点：** 默认代理模式下，同类自调用不会重新触发内层事务拦截；但外部通过代理进入的 `saveLeasedMessage` 已开启事务，其内部 JDBC 操作仍在该事务里。因此不能机械地说“自调用导致整个方法没有事务”。如果需要内层独立传播属性，应调整代理调用边界或使用编程式事务。[Spring 事务注解说明](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/annotations.html)。

**项目依据：** `TutorRepository.saveLeasedMessage/saveMessage`。这是一道很适合区分熟悉术语与理解运行机制的题。

### 23【P0】为什么干预创建使用 TransactionTemplate？给整个 create 加事务会怎样？

**连续追问：** 模型生成成功、创建审批失败，哪些数据应保留？requestApproval 是否加入同一事务？

**回答要点：** 当前先完成模型生成和网关审计，再在短事务中同时保存干预与审批。模型等待不占用这段业务事务的锁和连接。`requestApproval` 通过另一个 Bean 调用，默认 REQUIRED 加入现有事务。审批创建失败时干预应一起回滚，但真实发生的模型调用审计不应因此消失。

**项目依据：** `InterventionService.create`。这是“业务创建原子性”和“外部调用事实保留”两种语义的分离。

### 24【P0】为什么数据库事务不应该包住几十秒模型请求？

**连续追问：** READ COMMITTED 能否解决长事务问题？连接池占满怎样表现？模型成功后数据库失败怎么办？

**回答要点：** 长事务可能长时间占用连接与锁，扩大回滚成本，并影响数据库维护与并发。隔离级别不会消除外部依赖的不确定性。通常先短事务登记任务或领取处理权，外部执行后再短事务确认；同时准备超时、过期回收、结果不确定和幂等恢复。

**项目依据：** 会话租约是跨模型等待维持业务互斥的状态记录，数据库行锁只在短暂持久化时使用，两者不是同一种锁。

### 25【P0】项目为什么用 Session 而不是 JWT？多实例怎么做？

**连续追问：** JWT 是否天然更安全？注销、权限变化和服务端踢下线如何处理？粘性会话够不够？

**回答要点：** 当前浏览器同源应用使用服务端 Session，认证恢复和注销较直观。多实例要明确会话存储与失效策略，可选择共享 Session 或外部身份系统；粘性会话仍有节点故障和发布迁移问题。JWT 减少某些会话查询，但带来签名验证、有效期、撤销与权限变更处理，不是自动更优。

**项目依据：** `HttpSessionSecurityContextRepository`、`SessionCreationPolicy.IF_REQUIRED`。当前没有共享 Session 依赖，不能声称已实现多节点登录态共享。

### 26【P0】解释登录前后 CSRF Token 和 Session ID 的变化。

**连续追问：** permitAll 的登录接口为什么仍要 CSRF？SameSite=Strict 能否替代 Token？HttpOnly 防什么？

**回答要点：** 前端先取 Session/CSRF；登录校验凭据后更换 Session ID，保存认证上下文，并生成新 CSRF Token。permitAll 只是访问授权，不自动取消 CSRF 检查。HttpOnly 限制脚本读取 Cookie；SameSite 控制跨站携带行为；CSRF Token 校验请求来源关联，职责不同。

**项目依据：** `AuthController.login`、`SecurityConfig`、application 的 Cookie 配置。需要能说明登录固定会话攻击为何通过更换 ID 缓解，以及登录后的旧 CSRF 为什么应失效。

### 27【P0】只校验角色，是否已经完成权限控制？

**连续追问：** 一个教师能否修改本租户任意课程？学习者能否访问未报名课程？会话归属通过后能否更换 courseId？

**回答要点：** RBAC 控制接口类别，资源授权还要校验课程归属、报名关系、授课关系和对象状态。当前助教 `belongsTo` 检查会话租户与用户，但没有核对传入 courseId 与已保存会话课程；画像读取失败还会降级为空。这是应补充测试和资源校验的入口，不能声称“所有课程越权已被消除”。

**项目依据：** `SecurityConfig`、`TutorService.run`、`TutorRepository.belongsTo`。进一步设计可从已授权会话加载课程 ID，避免继续信任客户端选择。

### 28【P0】为什么不能从 X-Tenant-Id、X-User-Role 获取真实身份？

**连续追问：** 放在内网就可信吗？网关传来的 Header 如何验证？traceId 能不能作为幂等键？

**回答要点：** 普通客户端 Header 是声明，不是认证证据。当前租户和角色来自服务端认证主体。若以后由可信网关注入身份，还要保证入口隔离、剥离外部同名 Header、服务间认证和可验证身份声明。traceId 用于关联且可由客户端提供，不能默认唯一、不可伪造或具有权限语义。

### 29【P1】Spring Security 的过滤器顺序为什么重要？异常为什么不都进入 ControllerAdvice？

**连续追问：** TenantContext 应在认证前还是后构造？未认证、无角色、CSRF 失败分别如何响应？SSE 已提交后还能改 HTTP 状态吗？

**回答要点：** 只有认证主体建立后才能生成可信租户上下文。安全链中的错误通常由 Security 的入口点和拒绝处理器输出；MVC 业务异常由 MVC 处理。流式响应一旦提交，后续业务错误需要流内事件和前端协议，不能再依赖普通 JSON 错误响应。

### 30【P1】BCrypt、账号状态和接口暴露还需要注意什么？

**连续追问：** 工作因子 12 为什么不能拍脑袋？用户被禁用后已有 Session 呢？Actuator 是否全部受保护？

**回答要点：** 密码哈希成本需在目标机器验证并配合登录限速，不能记录密码。账号停用后已有 Session 是否立即失效，应有明确策略。当前 health/info 放行而其余 actuator 需审计角色；配置 `health.show-details: always` 值得审查公开信息范围。默认安全 Cookie 还依赖生产 HTTPS 配置。

## 第四组：数据库、多租户、一致性与迁移（31—40）

### 31【P0】所有表加 tenant_id，就能保证多租户隔离吗？

**连续追问：** JOIN 漏条件怎么办？外键如何阻止跨租户关联？后台任务和向量库呢？

**回答要点：** 还要覆盖读写条件、JOIN、缓存键、向量过滤、后台任务和日志/导出。当前一些会话子表没有 tenant_id，依赖先校验父会话，再按 ID 操作；不能概括为每条 SQL 都直接带租户条件。引用仅有 `FOREIGN KEY(course_id)` 也未必约束引用者与课程的 tenant_id 相同。

**项目依据：** V1/V7、`TutorRepository`。可比较复合约束、Repository 参数约束与 PostgreSQL RLS 的多层防护，明确后者是扩展方案。

### 32【P0】数据库会话租约如何避免两个请求同时生成？

**连续追问：** 为什么不用 JVM synchronized？WHERE 条件如何保证只有一个赢家？租约和行锁有什么区别？

**回答要点：** acquire 使用条件 UPDATE，仅当没有 owner 或已过期时赋新 owner/到期时间，以影响行数判断是否成功。共享数据库可跨实例竞争；JVM 锁只能协调本进程。租约行是持久状态，模型等待期间不保持长事务行锁。未获取到租约返回 CONVERSATION_BUSY。

**项目依据：** `TutorRepository.acquire`、`TutorService.run`。必须指出租约有效性仍受时钟、最大耗时和最终写入校验约束。

### 33【P0】租约过期后旧请求恢复，怎么防止它覆盖新结果？

**连续追问：** 只在开始时校验够不够？旧请求能释放新请求的锁吗？需不需要 fencing token？

**回答要点：** 当前最终写入时先锁住会话行，再验证 owner 与未过期条件；释放时也带 owner 条件。因此旧 owner 无法按这些路径误释放新 owner 的租约。外部资源若无法检查 owner，需要讨论单调 fencing token 或其他防旧写协议。当前 UUID owner 是持有者标识，不是单调 fencing token。

**项目依据：** `assertLease/saveLeasedMessage/saveMemory/release`。同时考虑进程崩溃后依靠租约到期恢复，没有自动续租逻辑。

### 34【P0】为什么消息需要 message_seq，而不只按 created_at 排序？

**连续追问：** 同一时间戳如何排序？MAX(seq)+1 会怎样？唯一索引有什么作用？

**回答要点：** 稳定序号支持历史顺序与摘要覆盖游标。当前在短事务中更新会话计数再写消息，以行锁串行化序号分配，唯一索引约束 `(conversation_id,message_seq)`。MAX+1 无并发控制会撞号。序号保证排序，不保证消息一定组成完整问答，失败请求仍可能留下 USER。

**项目依据：** `TutorRepository.saveMessage`、V7。旧数据按 `(created_at,id)` 回填只能得到稳定顺序，不能还原原本不存在的精细时间证据。

### 35【P0】摘要版本号和 covered_through_seq 为什么都需要？

**连续追问：** 一个字段能否替代另一个？摘要失败能否推进游标？保存摘要与游标应该分两次 UPDATE 吗？

**回答要点：** through 表示哪些消息已被覆盖，version 表示本条记忆更新次数及并发前提，两者语义不同。必须在同一次更新中持久化摘要、游标和版本。使用 `WHERE version=?` 防止以陈旧摘要覆盖更新结果；零行更新代表冲突。失败时保留旧摘要和游标。

**项目依据：** `TutorRepository.saveMemory`、`ConversationSummaryService.summarize`。还应解释初次插入 version=-1 的特殊路径和会话行锁。

### 36【P0】日 Token 聚合的 UPDATE 后 INSERT 有什么并发漏洞？

**连续追问：** UPDATE 自增本身是否会丢更新？两个首次请求同时到达呢？加 @Transactional 是否足够？

**回答要点：** 已存在行上的 SQL 自增和“行不存在时的竞争”必须区分。若 A、B 都 UPDATE 0 行，再 INSERT 相同复合主键，会发生唯一键冲突，可能回滚该请求的审计事务。PostgreSQL 可用 `INSERT ... ON CONFLICT (...) DO UPDATE SET ... = 当前值 + EXCLUDED...` 实现原子 upsert，但仍需要独立事件幂等，避免重放重复累计。[PostgreSQL INSERT 文档](https://www.postgresql.org/docs/current/sql-insert.html)。

**项目依据：** `AiAuditService.accumulateDailyUsage`、V1 聚合表主键。这是源码推导的竞争窗口，本次未执行并发复现。

### 37【P0】如果只准优化三条 SQL，你先看哪些，如何设计索引？

**连续追问：** 月预算查询为何可能变慢？审批列表索引匹配吗？联合索引第一列如何选？

**回答要点：** 从调用频率、扫描行数和等待时间定位，而非凭代码长度。候选包括每次模型调用的月用量聚合、长会话历史查询、审批列表。审计已有 `(tenant_id,created_at)`；日聚合主键以 usage_date 开头，可比较租户优先索引。审批现有 `(tenant_id,status,requested_at)`，无 status 条件的全量列表未必能直接利用期望的时间排序。

**项目依据：** `TokenBudgetService`、`TutorRepository.messages`、`ToolApprovalRepository.list`。提出索引后用真实目标数据库执行计划验证，还要考虑写放大与空间。

### 38【P1】V7 迁移在千万级 tutor_message 表上有什么风险？

**连续追问：** 相关 COUNT 回填的代价是什么？如何做到旧版与新版共存？什么时候加 NOT NULL 和唯一约束？

**回答要点：** 当前每行计算历史计数的写法在大表上可能昂贵，并伴随大事务、日志与锁风险。生产迁移应在同规模副本评估，可用窗口排序生成映射、分批回填、灰度双写、验证唯一性后再收紧约束。在线迁移方案需考虑写入期间新旧序号的协调，不能简单把一次 UPDATE 改成批量就宣布安全。

**项目依据：** `V7__tutor_context_memory.sql`、`TutorContextMigrationTest`。当前迁移测试不等于大表在线迁移验证。

### 39【P1】H2 的 PostgreSQL 模式测试通过，能否证明生产 PostgreSQL 正确？

**连续追问：** 行锁、死锁、时间戳、JSON、UPSERT、隔离级别分别怎样验证？

**回答要点：** 兼容模式便于本地开发，不能替代真实数据库。关键并发测试应在目标 PostgreSQL 上跑，包括首次聚合、重复审批、相反决策、租约到期、迁移与时区边界；可在 CI 中使用容器化数据库。H2 快速回归和 PostgreSQL 契约测试承担不同职责。

### 40【P0】模型成功了，审计写库失败了，接口应该成功还是失败？

**连续追问：** 重试会不会重复扣费？审计和业务结果是否必须同事务？异步审计丢了怎么办？

**回答要点：** 先定义场景要求。高风险工具动作需要持久可追踪证据才能进入执行；普通助教可讨论可用性优先但必须可靠补录。设计稳定调用 ID、结果状态、可靠事件落盘、去重聚合和对账。当前同步路径将审计写入放在成功逻辑中，失败可能进入异常分支再尝试记录；流式失败审计部分是 best effort，需要审查不确定状态。

### 45【P0】为什么租户和课程过滤要尽量在向量召回阶段完成？

**连续追问：** 先全库 TopK 再过滤会怎样？过滤越严格召回率越高吗？怎么证明没有跨租户内容？

**回答要点：** 先全库召回会让其他租户占据候选名额，过滤后可能无结果，也扩大错误日志或缓存泄漏面。检索前的权限约束是数据访问条件，不应依赖提示词。过滤缩小候选域，ANN 的召回和性能仍需评估。空 courseId 在当前实现中代表租户范围搜索，也要明确接口权限。

**项目依据：** `VectorStore.search` 的 tenant/course 参数和 Milvus filter。用不同租户的相同关键词与相似文档构造负向测试。

### 46【P0】TopK=4、最低分 0.05 是否能保证答案质量？

**连续追问：** 如何确定阈值？检索为空时系统做了什么？相似度高是否代表事实正确？

**回答要点：** 分数依赖模型、度量和语料分布，不是概率置信度。应使用标注集合选阈值，区分可回答和不可回答查询。当前搜索允许为空，助教系统提示词要求资料不足时说明，但代码没有统一硬性“无资料直接拒绝模型调用”。是否设硬拒答，要按课程问答范围设计并评测。

**项目依据：** `KnowledgeService.search`、`TutorService.SYSTEM_PROMPT`、`TutorContextBuilder.build`。不能将提示词要求说成服务端已经验证的事实约束。

### 47【P1】用户说“资料里明明有，为什么搜不到”，你怎么排查？

**连续追问：** 是切分、Embedding、索引、过滤、TopK 还是模型的问题？怎么分阶段评测？

**回答要点：** 按文档原文 → Chunk 是否覆盖答案 → 索引状态/版本 → 查询向量版本 → 权限过滤 → 排名与阈值 → 上下文最终保留 → 模型使用证据逐段检查。离线使用 Recall@K、MRR 或排序指标评估检索，再单独评估答案忠实度和引用支持率。先定位再考虑关键词混合检索或 reranker。

**项目依据：** 当前已有 Chunk、分数、引用、上下文尝试记录，但尚无完整召回评测集；混合检索和重排是扩展设计。

### 48【P0】知识文档保存成功，向量写入失败，会发生什么？

**连续追问：** @Transactional 能回滚 Milvus 吗？INDEXED 状态可信吗？客户端重试会不会重复建文档？

**回答要点：** 当前先在数据库事务中插入文档和 Chunk，文档直接标 INDEXED，再生成向量并 upsert。后续失败不能回滚已提交关系库，导致状态与实际索引不符。建议文档/版本与 outbox 事件同事务写入，异步处理 PENDING→INDEXING→INDEXED/FAILED，按稳定文档版本和 Chunk ID 幂等重试，辅以补偿扫描。

**项目依据：** `KnowledgeService.ingest`、`KnowledgeRepository.insertDocument`。这是已经能从执行顺序看出的故障窗口，不是已上线的异步索引能力。

### 49【P1】启动时全量重建索引有什么问题？多实例会怎样？

**连续追问：** 真实 Embedding 会调用多少次？服务 readiness 如何处理？一个 Chunk 失败是否影响启动？

**回答要点：** 当前应用就绪事件中读取全部 Chunk，并逐条向量化后批量 upsert。数据增长会增加启动耗时、内存与模型成本；多实例重复启动会重复工作，且本地内存索引实例间不会自动传播新增内容。可把向量和模型版本持久化，索引重建做成独立可恢复任务，分页、批量、限流并隔离单条失败。

**项目依据：** `KnowledgeService.rebuildRuntimeIndex/toVectorChunk`。即使配置 Milvus，该监听器当前仍会运行，不能只把它当作内存模式专用行为。

### 50【P0】替换 Embedding 模型，为什么不能只改环境变量？

**连续追问：** 维度一样能否混用？如何无停机重建？历史引用怎样追踪文档版本？

**回答要点：** 即使维度相同，向量空间也可能完全不同；文档与查询必须使用匹配模型和处理版本。应记录 embedding model/version、维度、切分版本，建立新索引并验证后切流，保留旧版本以回滚。文档更新需要明确旧 Chunk 下线和引用保留策略。

**项目依据：** 目前配置有模型名与维度，但适配器依据供应商实际返回数组构造向量；仅声明 dimensions 不会自动改变供应商返回维度。当前文档 version 固定写 1，没有完整更新发布流程。

## 第六组：上下文窗口、会话摘要与有限重试（51—60）

### 51【P0】上下文窗口和每月 Token 预算有什么区别？输入预算怎么算？

**连续追问：** 为什么必须为输出留空间？系统提示词、消息格式算不算？默认预算具体多少？

**回答要点：** 窗口限制一次模型调用可容纳的输入与输出；月预算限制租户累计消费，二者独立。当前主回答输入预算 `floor(16384×0.90)−2048=12697`，摘要输入预算 `floor(16384×0.90)−800=13945`。构建器估算系统文本、渲染后的全部输入，再加 32 的消息格式余量。

**项目依据：** `TutorContextProperties.inputBudget/summaryInputBudget`、`TutorContextBuilder.tokens`。配置代表应用预算，不是从供应商自动发现的模型能力。

### 52【P0】字符启发式 TokenEstimator 会出现什么误差？

**连续追问：** 中文、英文、代码、Emoji、长数字有什么不同？10% 安全边际足够吗？

**回答要点：** 当前部分 CJK 按一个 code point 估一个 Token，其他非空白字符约四个估一个。这不是 tokenizer，忽略空白和只识别部分 CJK 区块都会产生误差；消息序列化也有开销。应记录估算与供应商实际输入的偏差分布，按模型校准，并保留明确超限错误恢复。

**项目依据：** `TokenEstimator`。不能用“已经预留 10%”推出一定不会超限，也不能把估计值直接当供应商最终账单。

### 53【P0】为什么同时使用摘要、最近历史、画像和检索资料？

**连续追问：** 四类信息哪个可信？旧画像能否写进摘要？为什么历史引用编号不能复用？

**回答要点：** 摘要保存有损会话记忆；最近历史保留语境和纠错；画像来自当前数据库；课程资料提供本轮事实证据。摘要和对话都不应获得系统指令权限。引用编号与本轮最终资料列表绑定，旧“资料1”可能对应别的文档，不能作为当前证据。

**项目依据：** `TutorContextBuilder.render`、`ConversationSummaryService.SYSTEM`、助教系统提示词。摘要不能替代原始消息或权威课程内容。

### 54【P0】增量摘要如何避免每次重复压缩整段历史？

**连续追问：** 摘要什么时候触发？一次处理多少轮？历史积压太长怎样办？

**回答要点：** 先按 memory.through 取尚未覆盖消息；候选输入超过预算才触发摘要。将旧摘要与能放入摘要窗口的连续早期对话合并，优先保留最近两轮，每个业务请求最多做一次摘要。成功后推进到本批最后序号，后续请求继续处理积压。不是一轮请求保证把全部历史压缩完。

**项目依据：** `TutorService.run`、`ConversationSummaryService.summarize`。单条旧问答过长会使批次为空，不推进游标，本轮依靠裁剪降级。

### 55【P0】上下文仍然超预算时，按什么顺序裁剪？为何这样选？

**连续追问：** 能否截断当前问题？最低要保留几条资料？“保留最近两轮”是否硬约束？

**回答要点：** 当前依次删除低相关资料直到只剩一条、最早问答轮、画像、摘要；系统指令和完整当前问题不裁剪。如果原本有资料，保留至少一条；原本零条不会凭空补资料。最近两轮是摘要阶段的偏好，紧急裁剪仍可能删除。最小必要输入仍过大返回 CONTEXT_INPUT_TOO_LARGE。

**项目依据：** `TutorContextBuilder.build/removeOldestTurn`。能讨论为何不采用统一 substring，以及任务不同是否需要不同裁剪优先级。

### 56【P0】摘要返回无效 JSON、超时或被策略阻断时如何处理？

**连续追问：** 能否保存半个摘要？什么错误允许降级？摘要里的恶意内容怎么防？

**回答要点：** 只接受唯一字符串字段 summary，校验非空、长度和安全处理后才保存。普通解析/质量失败或摘要超时保留旧记忆并裁剪降级；网关策略阻断、月预算耗尽、租约丢失会向上抛出，取消也应终止。当前本地摘要后检查不通过抛普通参数异常，外层会降级，因此要准确区分“网关阻断”与“摘要内容验证失败”。

**项目依据：** `ConversationSummaryService.summarize`、`TutorService` 的异常分类。这一细节比笼统说“所有摘要失败都 fallback”更准确。

### 57【P0】为什么供应商上下文超限最多只重试一次，且必须尚未输出？

**连续追问：** 普通 HTTP 400/429 能否重试？已输出两句话后重试会有什么问题？

**回答要点：** 只对明确的 MODEL_CONTEXT_OVERFLOW 做有针对性的输入缩减。新预算取原预算的 75% 与上次实际估算减一中的较小值，保证确实变短。已发非空 delta 后重试会让前端拼接两个不一致答案并使引用混乱，因此不自动重试。无限重试还会放大费用和延迟。

**项目依据：** `TutorService.run`、`OpenAiCompatibleModelClient.providerError`。当前没有通用 429/5xx 退避机制，别把受限超限恢复描述成完整熔断重试框架。

### 58【P0】重试怎样避免重复保存用户问题和引用错位？

**连续追问：** 重试是否重新查历史、重新摘要？引用什么时候发送？业务 requestId 与 attempt 有何关系？

**回答要点：** 当前 USER 保存位于主回答尝试循环之外，重试复用同一历史快照和已得摘要，重新裁剪但不重新摘要。引用由最终实际保留的 hits 生成，在本次尝试首个回答片段前发出，done 再附最终引用。trace 后缀区分摘要与主回答重试，attempt 表记录预算、条数、降级和结果。

**项目依据：** `TutorService.run/citations`。这只防止同一个内部重试循环重复保存，不保证用户刷新后重新 POST 同一问题不会重复。

### 59【P0】“统一 60 秒截止时间”是否意味着所有 I/O 都会在 60 秒内被中断？

**连续追问：** 检索或 Embedding 在摘要之前卡住怎么办？每次重试都给 60 秒会怎样？

**回答要点：** 当前 Operation 用同一 deadline，模型等待取剩余时间与单次上限的较小值；摘要上限 15 秒。可是 deadline 是协作检查，不会自动中断所有阻塞 I/O。检索/Embedding 与若干 RestClient 路径没有在此处显式设置并传播同一剩余预算，应审查连接、响应体读取、数据库和队列等待的超时覆盖。

**项目依据：** `TutorService.Operation/invoke`、Embedding 和 Milvus 适配器。准确表述是“模型编排共用截止时间”，并说明端到端硬截止仍需验证。

### 60【P1】用户纠正以前说过的事实，摘要怎样保持正确？

**连续追问：** 只保留最新一句是否安全？多轮摘要会不会漂移？如何量化摘要质量？

**回答要点：** 摘要需区分用户陈述、助手建议、纠正关系、待解决问题与约束，避免把推测升级为事实。保留原始消息用于追溯，并以当前画像覆盖过时画像。评测包括重要事实保留率、错误新增、纠正采纳和跨批漂移；可用覆盖序号关联原文证据。

**项目依据：** 当前摘要提示词有相关约束，但本地 Mock 为固定摘要，不能用单元测试成功证明真实语义记忆质量。

## 第七组：SSE、网络协议、取消和流式状态机（61—70）

### 61【P0】为什么助教使用 SSE？什么时候需要 WebSocket？

**连续追问：** SSE 是否必须 GET？本项目为什么 POST？原生 EventSource 能直接带这个 JSON 请求体吗？

**回答要点：** 此场景主要是一次请求后服务端连续推送文字，HTTP 流符合需求。当前 POST 返回 text/event-stream，可由 fetch 读取响应流；原生 EventSource 的接口限制不能直接满足这个 POST JSON 交互。若需要持续双向音频、频繁控制消息或多路会话，再比较 WebSocket。协议选择应考虑鉴权、取消和部署链路。

**项目依据：** `TutorController.chatStream` 与静态页面 `app.js`。不要把 SSE 与原生 EventSource 混为一谈，也不要声称 SSE 天生不能用于 POST 响应。

### 62【P0】start、citations、delta、done 为什么分成不同事件？

**连续追问：** heartbeat 算业务事件吗？什么时候可能先收到 status？空回答如何处理？

**回答要点：** start 提供会话等元信息；citations 对应实际最终上下文；delta 增量更新；done 代表应用完成并携带统计；status 展示摘要/重试阶段。heartbeat 是 SSE 注释，不是回答内容。客户端应显式处理失败、取消、重复终态和在途状态，而不是只把所有文本拼起来。

**项目依据：** `TutorController`、`TutorService.TutorStreamListener`。当前常见顺序为可选 status → start → citations → delta → done；超限恢复可能插入新的 status。

### 63【P0】为什么需要 DeferredDelivery？模型回调可能早于方法返回吗？

**连续追问：** Mock 同步触发 delta 会发生什么？只在返回 stream 后发 start 行不行？缓冲区能否无限增长？

**回答要点：** 部分实现会在生成流句柄返回前调用消费者。直接转发会导致前端先看到 delta 再收到 start。当前先暂存回调，取得句柄、注册取消和发送 start 后再释放暂存数据。进一步审查缓冲上限和 consumer 在同步锁内执行的阻塞风险。

**项目依据：** `TutorService.DeferredDelivery` 和事件顺序测试。这是异步 API 的时序契约问题，不只是 Mock 的特殊兼容代码。

### 64【P0】浏览器在首个 Token 前关闭页面，服务端怎么知道？

**连续追问：** 没有输出时能否立刻察觉断网？heartbeat 有什么作用？取消在哪些层传播？

**回答要点：** 浏览器主动中止、Servlet 错误/完成/超时回调以及 heartbeat 写失败共同触发取消。传播链为 emitter → TutorStream/Operation → AiStreamingCall → AiModelStream → HTTP Future/响应体。首 Token 前也有 heartbeat，以便发现写侧断连；实际检测时间受代理与网络状态影响，不能承诺恰好一秒。

**项目依据：** `TutorController.StreamCancellation`、`TutorStreamingDisconnectIntegrationTest`。测试使用本地伪供应商验证真实连接关闭，不能替代所有网络环境测试。

### 65【P0】取消比 stream 句柄注册更早到达，怎样避免资源泄漏？

**连续追问：** attach 和 cancel 的所有交错顺序能否覆盖？单靠 if(stream!=null) 够吗？

**回答要点：** 先记录取消请求，即使资源尚未存在；资源 attach 后再次检查取消标记并立即取消。当前 Controller 的 requested 与 AtomicReference、Operation 的同步 attach/cancel、供应商的 cancelled 与 responseLines 都在处理这个竞态。写测试时用屏障控制“先取消后 attach”和“先 attach 后取消”。

**项目依据：** 三层取消对象。能画出交错时序，并指出每层资源所有者，才算真正理解取消实现。

### 66【P0】如何解析供应商 SSE？TCP 一次读取等于一条事件吗？

**连续追问：** 注释、多行 data、空行、usage-only 事件、[DONE]、错误事件怎么处理？

**回答要点：** TCP 不提供业务消息边界。当前按文本行读，以空行分隔事件，多行 data 拼接，忽略注释，解析 delta 和 usage，遇到 [DONE] 完成，解析 error 为业务错误。连接 EOF 但未见完成标记，应视为流中断，不能保存为完整回答。

**项目依据：** `readStreamingResponse/consumeEvent`。还可追问单事件大小上限、异常编码和坏 JSON；目前实现不等于支持所有供应商的全部 SSE 扩展。

### 67【P0】模型正常完成和用户取消同时发生，最终审计应该是什么？

**连续追问：** CAS 谁先成功？模型完成但客户端没有收到 done，算成功还是取消？数据库保存回答和网络确认能原子吗？

**回答要点：** 需要区分模型完成、业务持久化和客户端交付三个状态。当前每层终态只允许一个赢家，但并没有跨数据库与网络的原子提交。模型成功可能已计费和落库，done 却发送失败。更完整的观测应分开记录 generation_status、persistence_status、delivery_status，避免一个 SUCCESS 混淆所有语义。

**项目依据：** `AiGateway` terminal、`TutorService` 保存消息、`TutorController.onComplete`。这是状态建模题，不能仅回答“加原子变量”。

### 68【P1】一个客户端读取很慢，会拖慢整个系统吗？如何设计背压？

**连续追问：** SseEmitter.send 是否一定不阻塞？心跳线程池只有四个会怎样？能直接丢 delta 吗？

**回答要点：** 需要验证容器与网络写入行为；慢消费者可能拖住发送、模型读取或心跳任务。设计有界缓冲、发送超时、连接级取消与并发隔离。回答 token 通常不能任意丢弃，否则文本损坏；缓冲满可终止该连接并保留明确状态。定时池还应避免单个连接长期占用工作线程。

**项目依据：** `TutorController.heartbeatExecutor`、同步 listener 回调。这是需要负载测试验证的风险，不应从线程数直接断言线上已发生阻塞。

### 69【P0】为什么助教可以流式返回，而干预通知必须先拿到完整输出？

**连续追问：** 输出安全检查在最后执行，还能拦住已经发送的内容吗？能逐 token 检查吗？

**回答要点：** 已发出的文本无法靠最终后置检查撤回。干预会进入敏感动作流程，当前强制缓冲完整输出，检查内容后才允许生成审批。助教当前后置 Middleware 不做同样的完整输出安全处理。若增加流式内容审核，需要说明分段缓冲、延迟、跨段语义与最终漏检之间的取舍。

**项目依据：** `PostModelMiddleware.requiresBufferedOutput/process`、`AiGateway.executeStream`。不能说所有 AI 输出都经过了同一套强后置检查。

### 70【P1】SSE 断线重连能否自动继续生成？如何设计可靠重放？

**连续追问：** 使用 Last-Event-ID 就足够吗？POST 重发会不会再调用模型？服务重启怎么办？

**回答要点：** 当前协议没有已实现的可靠事件重放与业务请求去重，重发可能开启新生成。若要恢复，需要稳定 operationId、事件序号、持久或有保留期的事件日志，以及“继续订阅”和“重新生成”的不同 API 语义。还要决定原客户端断开时是否终止生成，与当前节省资源的取消策略协调。

**项目依据：** 当前事件没有可用于可靠恢复的持久 ID。引用和最终结果也必须跟随同一操作版本，不能拼接两个生成任务。

## 第八组：人工审批、工具执行与外部副作用（71—80）

### 71【P0】为什么模型不能直接调用 sendLearnerNotification？

**连续追问：** 高风险由谁判断？提示词要求“先请示”够不够？模型是否在自主选择工具？

**回答要点：** 生成内容不代表获得业务执行授权。当前编排服务显式创建敏感工具调用，Middleware 持久化待审批参数，不直接执行；教师批准才恢复工具。风险字段由应用装配，不能由模型任意降级。当前是受控工具编排，不是已经实现自主规划、多轮动态 function calling 的通用 Agent。

**项目依据：** `InterventionService.create`、`ToolExecutionMiddleware.requestApproval`。应能说清楚模型、编排器、审批人、执行器各自的权力边界。

### 72【P0】请画出审批状态机，重复和相反操作分别如何处理？

**连续追问：** 批准后再批准呢？拒绝后批准呢？两个教师同时做相反决定呢？

**回答要点：** 当前状态为 PENDING_APPROVAL、APPROVED、REJECTED。待处理只能进入一个终态；相同决定重放已有结果，相反决定返回冲突。数据库行锁让竞争串行化，以先成功完成的决策为准；不是两次操作都返回成功。

**项目依据：** `ToolExecutionMiddleware.approve/reject` 和相反决策并发测试。可进一步讨论取消、过期、多级审批，但这些状态当前未实现。

### 73【P0】SELECT FOR UPDATE 和唯一约束为什么要同时使用？

**连续追问：** 有唯一键还需要行锁吗？两个实例会有效吗？锁住什么范围？

**回答要点：** 审批行锁保护读状态、执行数据库通知、变更状态的顺序；通知 approval_id 唯一约束作为防重复副作用的不变量保障。两者职责不同，唯一约束不会自动提供友好的状态重放和相反决策语义。共享数据库让多实例看到同一锁与约束。

**项目依据：** `ToolApprovalRepository.findForUpdate`、`ToolExecutionMiddleware.approve`、V6 的 `uk_notification_approval`。

### 74【P0】“通知插入成功，但审批状态更新失败”如何保证一致？

**连续追问：** 工具是否另开事务？异常被吞掉会怎样？所有 handler 都能放进这个事务吗？

**回答要点：** 当前通知是同数据源的数据库 INSERT，执行和状态变更均在批准事务里，失败应一起回滚。需要维持异常传播与同事务资源参与。若 handler 改成 REQUIRES_NEW 或外部 RPC，原先的原子性推导不再成立，必须重新设计。

**项目依据：** `ToolExecutionMiddleware.approve`、`LearnerNotificationTool.execute`。通用 Handler 接口的存在，不意味着所有工具天然共享数据库事务语义。

### 75【P0】把数据库通知换成真实短信，怎样避免重复发送？

**连续追问：** 短信已发送但服务崩溃怎么办？MQ exactly-once 能解决吗？供应商不支持幂等怎么办？

**回答要点：** 批准事务保存决策与 outbox；消费者按稳定事件 ID 发送，向供应商传稳定幂等键，记录供应商请求 ID 与回执。发送超时是结果未知，需查询状态或对账再重试。供应商不支持幂等或查询时，无法笼统保证端到端 exactly-once，应明确重复风险、补偿与人工处理。

**项目依据：** 当前仅数据库通知，outbox/MQ/短信均为设计扩展。区分决策已批准、投递中、已送达、最终失败，不要让 APPROVED 兼任送达状态。

### 76【P0】审批参数为什么要保存快照，而不是批准时重新生成？

**连续追问：** 教师批准的到底是什么？草稿被修改怎么办？模型版本更新会改变审批内容吗？

**回答要点：** 审批授权应绑定确定的对象、参数与版本，避免“看的是 A，执行的是 B”。当前保存 arguments_json，批准时读取既有参数执行。若允许修改草稿，应形成新版本并使旧审批失效；可记录参数哈希，但哈希本身不等于防篡改存储。

**项目依据：** `ToolApprovalRepository`、`LearnerNotificationTool.requiredArgument`。执行参数应来自被审批快照，不能被批准接口再次传入并覆盖。

### 77【P1】为什么首次批准后要重新读数据库记录再返回？

**连续追问：** Java Instant 与数据库时间戳精度有什么区别？副作用幂等和响应一致是否相同？

**回答要点：** 持久化可能截断时间精度。若首次响应使用内存 Instant，重试响应读取数据库，两个结果可能不完全相同。当前 markDecision 更新后读回持久态，以便重复批准重放一致表示。响应一致性不仅是“没有再插入通知”，还包括决策人、时间与评论稳定。

**项目依据：** `ToolApprovalRepository.markDecision` 及注释。这是可以用来展示接口设计细致程度的具体例子。

### 78【P0】当前审批是否满足四眼原则？如何防止权限变化后的过期授权？

**连续追问：** 发起教师能自批吗？等待期间学习者退课怎么办？审批应不应该过期？

**回答要点：** 当前允许教师显式自批，没有四眼限制。生产如果需要职责分离，应校验请求人与审批人不同及各自资源权限。执行时还要重新验证可变前提，例如账号、报名、课程、工具策略；快照保证被批准内容稳定，不代表所有外部条件永远有效。

**项目依据：** `InterventionService.create` 校验报名，而当前批准路径没有完整复查所有业务前提。过期审批和审批权限版本属于待设计能力。

### 79【P1】新增一个敏感工具，注册和兼容性要如何设计？

**连续追问：** 两个 Handler 同名怎么办？旧审批跨部署后找不到 Handler 呢？参数 schema 改了呢？

**回答要点：** 当前按 toolName 将 Handler 收集到不可变 Map，重复名会在构建时失败；批准时 Handler 缺失会保留待处理语义并报错。进一步应版本化工具名/参数 schema，维护历史参数迁移或兼容执行器，禁止任意字符串直接映射可执行方法。

**项目依据：** `ToolExecutionMiddleware` 构造器和 approve。可讨论工具白名单、资源类型绑定和最小执行权限。

### 80【P0】“重复批准不重复通知”是否等于整个干预流程幂等？

**连续追问：** 连点创建两次会产生几张审批单？客户端超时重试创建呢？

**回答要点：** 当前唯一约束以 approval_id 为边界，两次 create 会产生不同干预与审批，仍可能各发送一次。端到端创建幂等应使用业务请求键，绑定 tenant、actor、操作类型与请求内容哈希；重复键相同内容重放状态，不同内容冲突。还需覆盖并发占位、处理中和失败重试策略。

**项目依据：** `InterventionService.create` 每次新建 UUID。幂等必须说明作用范围，不能只说系统“做了幂等”。

## 第九组：AI 治理、预算、计费与可观测性（81—90）

### 81【P0】月预算先查询、调用后累计，为什么挡不住并发超支？

**连续追问：** 还剩 100 Token，两个请求各用 500 会怎样？只加锁查询足够吗？

**回答要点：** 当前只判断已用是否达到预算，未预估和预占本次需求。即使单线程，最后一次调用也可能越界；并发时多个请求看到同一剩余额度同时放行。硬配额需要原子预占输入估计与输出上限、调用后按实际用量结算或退款；预占记录要有稳定 requestId、过期与不确定状态处理。

**项目依据：** `TokenBudgetService.assertAvailable`。预算单位还要明确：累计 Token、金额或两者，而不是把模型窗口额度混进月配额。

### 82【P0】请设计一个不会因重试重复扣减的配额预占协议。

**连续追问：** 进程预占后崩溃怎么办？实际用量大于预占怎么办？跨月生成怎么归属？

**回答要点：** 预占记录按 tenant+operationId 唯一，状态可为 RESERVED、SETTLED、RELEASED、UNKNOWN。余额条件更新与预占插入在同一事务；调用后用幂等结算更新 used/reserved。到期不应一律退款：若上游可能已执行，应先对账。定义预算周期、统一时区和超预占策略；上下文估算误差也会影响预占可信度。

**项目依据：** 这是对现有软预算门禁的生产化设计，仓库尚未实现该状态表和流程。

### 83【P0】为什么失败、取消和输出被拦截，也可能应该计费？

**连续追问：** 供应商已生成答案但安全检查拒绝，Token 算谁的？取消拿不到 usage 呢？

**回答要点：** 用户收到成功结果与供应商消耗资源是不同事实。当前同步后置阻断保留已知 usage，取消用输入及部分输出估算；某些流式失败记为零，不代表真实零消费。建议使用量来源标记 ACTUAL/ESTIMATED/UNKNOWN，记录供应商请求 ID 并对账，避免把所有零值看成准确账单。

**项目依据：** `AiGateway.execute` 的失败分支、`recordStreamCancellation/recordStreamFailure`、`AiAuditService.record` 的聚合条件。

### 84【P0】BigDecimal 解决了费用准确性的全部问题吗？

**连续追问：** 缓存输入如何计价？不同模型和生效日期怎么办？币种与舍入在哪一层处理？

**回答要点：** BigDecimal 解决十进制计算中的一类精度问题，不解决价格来源与计量口径。当前单价是输入 0.80、输出 3.20 每百万 Token 的演示常量，记录 cachedTokens 但没有单独折扣。生产应记录供应商、实际模型、价格版本、币种、用量来源与舍入政策；缓存 Token 若包含在总输入内不能再额外相加。

**项目依据：** `AiGateway.estimateCost`。这些常量不能当作任何供应商当前真实价格或对外报价。

### 85【P0】输入正则 Guardrail 能防住提示词注入吗？

**连续追问：** 用户绕写、文档间接注入、误报教学内容怎么办？过滤后能否认为可信？

**回答要点：** 当前正则能识别部分明显模式，也可能漏报或误报；例如正常讨论 system prompt 的课程内容可能触发规则。检索资料、历史和摘要都应作为不可信数据处理。更可靠的边界包括权限控制、数据与指令分离、工具参数约束、最小权限、输出验证、攻击样本回归，不能仅依赖一句系统提示词。

**项目依据：** `GuardrailService.inspect` 和完整渲染输入进入网关的路径。被脱敏不等于被证明无恶意指令。

### 86【P0】所有发往外部模型的数据是否已经统一脱敏、计量？

**连续追问：** Embedding 经过 AiGateway 吗？知识检索前，用户问题是否已经发送出去？原始聊天保存在哪里？

**回答要点：** 当前查询 Embedding 在知识检索阶段直接调用 EmbeddingService，文档向量化也直接使用 Chunk 原文，并不经过 AiGateway 的输入脱敏、Token 月预算与调用审计。因此不能说所有模型外发都已纳管。聊天原始 USER 文本还会进入业务会话表，网关审计脱敏不等于全链路存储脱敏。

**项目依据：** `TutorService.run`、`KnowledgeService`、`OpenAiCompatibleEmbeddingService`、`AiGateway`。生产要盘点所有数据出口并按场景决定脱敏、最小化与独立计量。

### 87【P0】promptHash 和 responseHash 能证明什么，不能证明什么？

**连续追问：** Hash 是否加密？能否恢复原文？攻击者改内容再改 Hash 呢？

**回答要点：** 哈希支持内容一致性比对，不保密、不认证记录写入者，也不能阻止拥有写权限者连同哈希一起改写。当前 promptHash 来自原始系统提示词与用户材料，发送模型的用户材料可能已脱敏，审计解释时要区分原始与有效输入。更强证据需访问控制、签名/链式校验及独立追加存储。

**项目依据：** `AiGateway` 中 promptMaterial 的构造与 safeRequest。建议分别命名 original_input_hash/effective_input_hash，避免复现歧义。

### 88【P0】日志、Metrics、Trace、业务审计应该如何分工？

**连续追问：** tenantId 能不能放 Prometheus 标签？traceId 为什么不该放标签？请求量与模型调用量相同吗？

**回答要点：** 日志用于诊断事件，Metrics 用于低维聚合趋势，Trace 用于跨阶段因果耗时，审计用于持久调用与决策证据。用户 ID、traceId 等高基数标签会扩大时间序列数量，宜留在日志/Trace/查询存储。一次助教请求可能含摘要、主回答和重试，多次模型调用不等于多次用户请求。

**项目依据：** 当前 counter 使用 scenario/status/type/model；traceId 主要在 MDC 和数据库。存在 traceId 不等于已接入完整分布式 Trace。

### 89【P0】为什么平均延迟不足以监控 AI 服务？你要加哪些指标？

**连续追问：** 首 Token 慢但总耗时正常怎么办？输出被阻断能算成功吗？取消率升高一定是坏事吗？

**回答要点：** 加 TTFT、总耗时分位数、排队时间、检索/摘要/模型分段耗时、超限重试率、降级率、取消传播耗时和每次有效任务费用。平均值掩盖长尾。取消可能是用户主动离开，也可能因为等待太久；需与延迟关联。HTTP 200 的 SSE 也可能包含 error，业务成功率要按终态计算。

**项目依据：** 当前审计保存 latency，网关有请求/Token counter，但未见完整 TTFT 和分阶段直方图实现。

### 90【P1】审计里的 model 为什么可能与供应商实际返回不一致？

**连续追问：** 配置别名会不会解析到具体版本？模型自动路由后价格按谁算？为什么供应商请求 ID 要保存？

**回答要点：** 当前 `AiModelResponse` 可包含响应模型名，返回结果和部分指标使用它；但 `auditRecord` 使用 `modelClient.model()` 的配置值。供应商别名解析或路由时两者可能不同。应同时记录 requested_model/resolved_model/provider_request_id，以支持计费、事故排查和版本效果比较。

**项目依据：** `OpenAiCompatibleModelClient` 解析响应模型与 ID，`AiGateway.auditRecord` 的字段选择。响应对象有某字段，不代表该字段已经落入审计表。

## 第十组：业务算法与代码审查深挖（91—100）

### 91【P0】当前批改规则是否真的根据每份作业的 rubric_json 评分？

**连续追问：** 换成英语作文作业会怎样？学生堆关键词能得高分吗？怎样让分数可解释？

**回答要点：** 当前 evaluate 只看答案长度、固定 RAG/治理关键词和非空行数；rubric_json 进入模型提示词，但没有被解析为数值评分规则。因此它是特定演示主题的启发式算法，不是通用量规引擎。应把评分维度、权重、规则版本、证据跨度与作业绑定，准备对抗样本和教师标注校准。

**项目依据：** `GradingService.grade/evaluate`。固定权重为完整度 20%、架构 40%、治理 25%、清晰度 15%。

### 92【P0】confidence=0.85 是否代表评分有 85% 概率正确？

**连续追问：** 0.72 的复核阈值怎样确定？长但错误的答案是否可能高置信？

**回答要点：** 当前 confidence 是根据长度和关键词覆盖构造的启发式值，没有概率校准证据。长度足够就可能获得较高值，不能把它解释成统计正确率。应定义置信度对应的事件，例如分数误差小于某阈值，并用教师双标与验证集校准，再结合误判成本确定复核门槛。

**项目依据：** `GradingService.evaluate` 和 `confidence < 0.72`。AI_GRADED/HUMAN_REVIEW 是当前状态规则，不代表已实现完整复核队列、人工改分和学习闭环。

### 93【P0】每周 200 分钟、选四项技能，当前学习路径总时长是多少？

**连续追问：** 最低 20 分钟约束会造成什么？如何写不变量测试？预算不够怎么取舍？

**回答要点：** 每项 `max(20,200/4)=50`，四项用 200；检查点另加 `max(20,200/5)=40`，共 240，超出预算。改进先给检查点预留时间，再用剩余额度分配技能，预算不足时减少活动、缩短活动或明确不可满足，不能悄悄突破约束。

**项目依据：** `LearningPathService.createItems`。这是确定的算术推导，本次未执行自动测试；重要不变量是所有计划分钟之和不超过 weeklyMinutes。

### 94【P1】按掌握度从低到高排序，能保证学习路径合理吗？

**连续追问：** 前置知识依赖怎么办？两个技能同分怎么排序？evidence_count 低意味什么？

### 101【P0】假设峰值每秒 100 次提问、平均每次 20 秒，需要支持多少在途请求？

### 116【P0】现场编码：实现可取消、只允许一个终态的模型调用句柄。

**题目约束：** `completion()` 返回 Future；`cancel()` 可并发重复调用；上游响应体可能在取消之后才注册。

**参考实现思路：** 终态与资源注册分别建模，使用 CAS 或明确临界区协调；取消先记录意图，再关闭已注册资源；attach 发现已取消就立即关闭新资源。终态获胜后以 finally 保证 Future 最终完成或取消，避免审计抛异常留下永久未完成状态；阻塞关闭不要随意放进大锁。

**验收标准：** 先取消后 attach、先 attach 后取消、成功/取消竞争、失败/取消竞争、关闭抛异常、回调同步触发。还要说明 AtomicBoolean 的范围仅是单对象进程内协调。

### 117【P1】现场算法：百万候选只取 Top10，如何改进全排序？

**连续追问：** 时间复杂度、空间复杂度各是多少？相同分数如何稳定？并发更新是否影响快照？

**回答要点：** 对已计算分数的候选维护大小 K 的最小堆，通常为 O(M log K)、额外 O(K)，替代 O(M log M) 全排序；最后将堆输出降序。它不消除 O(MD) 的向量相似度计算，也不解决全库扫描，可再讨论分区或 ANN。相同分数用稳定 Chunk ID 打破平局，处理 NaN、零向量和维度错误。

**项目依据：** `InMemoryVectorStore.search`。这是基于项目的集合与算法题，追问重点是优化了哪一步、没有优化哪一步。

### 118【P0】你如何把一个复杂方案讲清楚并推动团队落地？

**连续追问：** 团队有人想先上微服务，你如何讨论？怎么分配任务与定义完成标准？

**回答要点：** 用现有问题和约束对齐目标，画出状态/事务边界和故障窗口，列两到三个方案的成本与风险，选择最小可验证阶段。任务按独立契约划分，如配额状态、网关接入、对账与压测；明确 owner、回滚开关和验收条件。讲清楚自己做了什么决策、别人提出什么有效反对意见。

**项目依据：** 可用“索引一致性改造”或“配额预占改造”做假设案例；没有真实团队实践时明确是设计演练，不编造组织成绩。

### 119【P0】请讲一次最复杂的问题定位，如何避免只讲故事不讲证据？

**连续追问：** 初始现象是什么？推翻过什么假设？什么证据锁定根因？如何防复发？

**回答要点：** 按现象与影响 → 时间线与数据 → 候选假设 → 排除过程 → 最小复现 → 修复 → 回归与观测讲。若用本项目演练，可选首 Token 前断连未取消、首次日聚合竞争、时间预算超分，但应标为代码推导/测试演练。真实线上故事必须来自你本人经历，指标有来源。

**项目依据：** 当前源码能提供机制和故障假设，不能证明你处理过这些生产事故。

### 120【P0】如果让你重新做一次，这个项目有哪些取舍会改变？

**连续追问：** 哪些设计会保留？一个月能交付什么？如何判断完成？

**回答要点：** 保留确定性决策与模型生成分离、统一网关、敏感动作审批、短事务和明确取消。优先重新界定资源授权、业务请求 ID、调用生命周期/审计事件、索引发布状态与配额预占。给出分阶段验收：跨租户测试不泄漏、同请求无重复副作用、无虚假 INDEXED、取消不持久化完整半答案、目标负载下有可解释的耗时和费用。

**项目依据：** 结合实际代码不足提出取舍，而不是把所有实现全部推翻，也不是把未完成能力包装成已有成果。
